## 能力

以"在平凡中发现不平凡的道理"为核心理念，从日常生活中的一件小事、一个场景、一个物件切入，通过对现象的多层追问和反思，最终抵达一个人生哲理层面。哲理散文不同于抒情散文（不以情感氛围为核心）和叙事散文（不以故事线索为骨架）——它的驱动力是"思考"，是从"这是什么"到"这意味什么"的智性旅程。说理但不训诫，追问但不说透，智慧藏在留白中让读者自己发现。

哲理散文的独特价值在于：把一个抽象的道理"做"成可见可感的生活画面，让读者读完不说"我懂了某句话"，而是说"我看到了一件事，我自己的理解改变了"。

## 调用方式

```
/哲理散文 <主题或素材>
```

## 输入示例

```
/哲理散文 地铁上那个一直站着的空位
/哲理散文 为什么我们总把最好的东西留到最后
/哲理散文 老屋的墙上有一道裂缝
```

### 范文核心技法提取

**22027（我们生活在巨大的差距里）**：余华用多个看似零散的片段串联全文——北京的摩登大厦、上海的外滩、西北老家的土路。这些片段本身并无逻辑关联，但并置在一起就产生了强烈的"差距感"。这种"并联式结构"不靠因果链条推进，而是靠意象的叠加让读者自己得出结论。核心技法：不让道理直接出场，让读者在阅读不同片段的对比中"自己发现"主题。

**206（无论你来自何处，长安有你容身之处）**：将"个人的微小经历"（一个外来者的城市感受）与"宏大的历史叙事"（长安一千多年的建都史）缝合在同一个文本里。个人感受为历史叙事提供温度，历史纵深为个人感受提供重量。技法核心是"大小切换"——在个人故事和历史讲述之间自然转换，不让任何一边喧宾夺主。

**24924（母爱的视角）**：全文围绕"看"这个动作展开——这是一个绝妙的"哲理锚点"。不写母爱的一般形态，而是聚焦于"母亲怎么看孩子"这个特定角度，将"母爱"这个宏大的主题压缩到一个日常动作中。每一段都从"看"出发，每一段都回到"看"，结构高度集中。哲理散文最怕的是"散"，而24924的答案是：用一个核心动作贯穿全篇，让所有思考围绕它展开。

**17285（中国城市的上半身和下半身）**：以"上半身/下半身"这个身体隐喻为结构骨架，把城市空间划分成两个层次，然后分层展开对比。这种"二元隐喻结构"天然具有张力——读者不需要等待作者下结论，对比本身就产生了思考空间。技法启示：找到一个有张力的二元隐喻（上半身/下半身、白天/黑夜、正面/背面），全文就在这个隐喻框架中展开。

**226（鲁滨孙是孤独的人吗）**：用一个经典文学形象来承载一个普世命题的重新定义。先提出一个看似常识的问题，然后用一个新的解读角度翻转常识——鲁滨孙不是孤独的，因为有星期五；而现代人才是真正孤独的，因为身边的人越来越多"不相关的人"。技法核心是"先用常识设靶，再重新解读翻靶"，让读者经历"我本来以为是这样——但原来不是——那到底是什么"的心理过程。

## 结构模板

### 开头（150-200字）：一个具体小事或场景

**写法指导**：哲理散文的开头要像"敲门"——用一个具体到让读者觉得"这我也经历过"的小事，轻轻推开思考的大门。不要从道理出发，要从画面出发。

```
可选开场方式：
- 场景式：一个日常的画面——"早高峰的地铁上，人们挤在一起，面无表情地看着手机。"
- 物件式：一个不起眼的东西——"家里的门锁已经用了二十年，每次转动都要偏一个角度才能对上。"
- 事件式：一个看似寻常的事件——"去朋友家做客，他打开冰箱，里面塞满了各种酱料——几乎没有一瓶是满的。"
- 问题式：一个从生活中自然浮现的疑问——"阳台上的富贵竹，换了一茬又一茬，为什么总养不活？"
```

示例开头句式（参考 22027）：
> "上个月去北京，朋友带我逛了三里屯。晚上九点，灯光璀璨，路上走着的年轻人都穿着得体，手里端着咖啡，说说笑笑。两天后回到老家县城的镇上，晚上九点街上已经没什么人，唯一还亮着灯的是路口的麻将馆。"

**关键**：不要用抽象概念开头。"人生的意义""幸福的本质""什么是爱"——这些是结论，不是起点。起点必须是一个"读者能看见的东西"。

### 展开（300-500字）：从现象追问本质，层层深入

这是文章的主体。哲理散文的推进方式不是"讲故事"，而是"做问答"——你不断问"为什么"，然后给出一个思考的方向，再追问"然后呢"，再深入一层。

**第一层（现象描述 + 初步质疑）**：回到开头的场景，写出"我看到的是A，但仔细想想，它可能不只是A"。把现象本身写透，提出一个可以追问的角度。

**第二层（追问 + 多角度审视）**：从"为什么会出现这个现象"出发，用不同视角审视同一件事。这个阶段可以用三种方式推进：
- **正反对比**（参考 17285）：同一个事物的两面（热闹/冷清、表面/内里、城里/城外）
- **古今/中外参照**（参考 206 和 22027）：现在和过去对比，此处和别处参照
- **举例拓展**：再用一个同类但不同的例子，让思考的层面拓宽

**第三层（反思路径 + 逼近本质）**：在前两层铺垫的基础上，抛出一个翻转性的追问——"真的是这样吗？""我们会不会一直想反了？"。这一层是哲理散文最珍贵的部分：它不止于描述现象，而是对"常识"提出质疑，让读者停下来重新思考。

**关键原则**（参考 24924 和 226）：
- 每个段落都要回答"然后呢？"——不是情节的"然后"，而是思考的"然后"
- 每个追问都应比前一个更深入一层，不能在同一层次反复打转
- 如果写了一段没有推进思考的文字，删掉
- 不要替读者下结论，留思考空间给他们自己

### 结尾（100-150字）：点到即止，不说教

**写法指导**：哲理散文的结尾是"余音"——不是收住，而是扩散。不说"那我们应该这样做"，而是写一个画面或一个意象，让读者自己品出道理。

- **画面收束式**：回到开头的场景或物件，但因为中间的思考，读者再看到它时已经多了层理解。"那把锁还在那里，每次转动的时候，我都不再觉得是它坏了。"
- **反问留白式**：用一个反问句收住，把结论交给读者。"如果长安可以容下天下人，那今天的我们，能容下那个和自己不一样的人吗？"
- **意象延展式**：用一个与主题相通但未在前文出现过的意象来收尾，让读者的思绪跟着这个意象飘远。"窗外的那棵树又长高了一截。它不说话，但它知道阳光从哪个方向来。"

禁止使用的结尾方式：
- "因此，我们应当……"式的说教结论
- "这个故事告诉我们……"式的箴言总结
- "这就是人生的哲理啊"式的直白揭示
- 用一段排比句强行煽情

## 技法要点

### 1. 比喻说理——把抽象哲理变成具体物象

哲理散文的核心难题是：如何把"看不见的道理"变得"看得见"？答案是比喻。但哲理散文的比喻不是修辞装饰，而是"说理的工具"。

**比喻即论证**：一个好的哲理比喻不只是"像"——它本身就是论证。比如用"城市的上半身和下半身"这个比喻来论证城市的二元性——比喻一旦成立，论证已经完成了一半。

**选择日常物象**：比喻的物象必须来自日常生活，读者一闭眼就能"看见"。不要用"像宇宙中的星辰"这类过于宏大的比喻。

| 抽象概念 | 好比喻（日常物象） | 差比喻（抽象空洞） |
|---|---|---|
| 人与人之间的隔阂 | "像两扇不在一条轨道上的推拉门" | "像银河一样遥远的距离" |
| 时间的流逝 | "像一把钝刀在切肉" | "像奔腾不息的河流" |
| 爱的局限 | "像一件织得太紧的毛衣" | "像阳光一样温暖" |

**比喻的节制**：一篇文章2-3个精妙的比喻即可。过多的比喻会让读者迷失在修辞中，忘记你在说理。

### 2. 对比推进——正反/古今/中外对比

对比是哲理散文最有力的推进手段。因为哲理本身往往来自"差异"——两件看似相同的事物放在一起，差异本身就在说话。

**三种对比类型**（参考 22027 和 17285）：

- **空间对比**（此处 vs 彼处）：同一个时间点，不同地方的人的活法——"你在北京三里屯喝咖啡的时候，你老家的人在做什么？"
- **时间对比**（过去 vs 现在）：同一个人、同一个地方，不同时间的状态——"小时候觉得那个菜市场又脏又乱，现在却觉得那里才是城市最有温度的地方。"
- **视角对比**（我看 vs 他看）：同一件事，不同视角的理解——"你觉得母亲在唠叨，但她可能只是想确定你还安全。"

**对比的排布方式**：
- 并列式（参考 22027）：多个对比片段平行排列，读者自己从中找结论
- 递进式（参考 24924）：对比一层比一层深入，最后得出一个翻转性的认识
- 先正后反（或先反后正）：先写"大家通常怎么想"，再写"但还有另一种可能"

### 3. 层层追问——为什么→然后呢→真的是这样吗

哲理散文的"思路线"由一连串追问组成。追问的质量决定了文章的质量。

**追问的三个层级**：

| 层级 | 问题 | 示例（围绕"菜市场"） |
|---|---|---|
| 第一层（现象） | 发生了什么？ | "为什么年轻人都去超市了，菜市场里只剩老人？" |
| 第二层（原因） | 为什么会这样？ | "超市更干净、更方便、更高效——这是不是意味着菜市场是'落后'的？" |
| 第三层（本质） | 真的是这样吗？ | "如果我们认为高效就是好、方便就是进步——那我们在失去什么？" |

**追问的原则**：
- 每一层追问必须比上一层更接近本质，不能在同一层来回问
- 追问到第三层（本质层）就收住——不要追问到"人生的意义"那种过大的问题
- 追问的答案是"开放"的——你可以指出方向，但不能包办结论

### 4. 克制议论——引而不发，不说透

哲理散文最大的陷阱是"说太多"。写作者一旦发现了某个道理，就迫不及待地全盘托出。但哲理的力量不在于"说"，而在于"让读者自己发现"。

**"三不说"原则**：
1. **不说结论**——把结论留在细节和对比中，让读者自己读出
2. **不说情绪**——不要催泪，不要煽情，冷一点反而有力量
3. **不说绝对**——"也许""可能""有时候"，这些词是哲理散文的护身符

**"引而不发"的技巧**（参考 22027）：
- 写到离结论只有一步之遥的时候，停下来，换一个角度
- 用一个意象代替一句说理——不说"时代在撕裂"，而是写"同一条街上，有人在吃高档日料，有人在垃圾桶里翻能卖钱的瓶子"
- 把问题抛给读者——用"这是为什么？"代替"这就是差距"

| 说得太透（避免） | 引而不发（推荐） |
|---|---|
| "这说明贫富差距太大" | "三里屯的灯光和县城老街的黑暗，被我坐的一趟高铁连接在了一起" |
| "母爱的方式各有不同" | "她看我的方式，和我希望被她看的方式，从来不在同一个焦距上" |

## 哲理散文 vs 抒情散文 vs 叙事散文

本 skill（哲理散文写手）与 `skill-lyrical-prose.md`（抒情散文）、`skill-narrative-prose.md`（叙事散文）互补但不重叠：

| 维度 | 哲理散文 | 抒情散文 | 叙事散文 |
|---|---|---|---|
| 核心驱动力 | 追问与思辨——"这意味什么" | 情感氛围——"感受到了什么" | 叙事线索——"发生了什么" |
| 结构重心 | 现象→追问→反思→顿悟 | 物象堆叠→情感递进 | 事件发展→夹叙夹议 |
| 输出目的 | 让读者"重新看待"一件事 | 让读者"感受到"一种情感 | 让读者"经历"一段故事 |
| 人物作用 | 作为思考的载体 | 作为情感的符号 | 作为叙事的推动者 |
| 比喻作用 | 说理工具——比喻即论证 | 情感载体——比喻即表达 | 场景辅助——比喻即画面 |
| 结尾 | 留白，留一个让读者继续思考的空间 | 留白，回到底物多一层意味 | 余韵，回到当下 |
| 字数 | 600-1000字 | 600-1000字 | 800-1200字 |

**选择原则**：
- 如果你不是在"讲故事"，而是在"想道理"——从一个具体的小事出发，层层追问"为什么会这样"，最后得出一个思考的结论——选哲理散文。
- 如果你有一件让你感动的事，想通过细腻描写传递那份感动——选抒情散文。
- 如果你有一段完整的人生经历，想通过叙事让读者"经历"一遍——选叙事散文。

## 风格特征总结

| 特征 | 说明 |
|---|---|
| 切入点 | 一个具体到"谁都经历过"的小事或场景 |
| 推进方式 | 追问驱动——每个段落都比前一个更接近本质 |
| 说理方式 | 比喻说理 + 对比说理，不直接讲道理 |
| 情感表达 | 克制、冷峻——"冷"比"热"更有哲理力量 |
| 结尾处理 | 点到即止——不说透，不总结，留余音 |
| 读者体验 | 读完后不是"我学到一个道理"，而是"我重新看待了某件事" |
| 语言风格 | 平实、洗练、节奏感强；句式长短交替；多用疑问句和短句制造思考停顿 |

## 输出约束

- **字数**：600-1000 字（中文）
- **署名格式**：文末空一行，右对齐署名，格式为 `文/XXX`（使用调用时指定的虚构作者名；如未指定，使用默认作者名"佚名"）
- **不允许**：直接说教、"我们要""我们应该"等训诫句式、政治议论、官方宣传口径、使用排比句强行煽情、替读者下结论
- **必须**：从一个具体物件/场景/事件切入、至少有一层"本质追问"（"真的是这样吗"层级）、有一段对比（正反/古今/中外/视角对比）、一个日常物象比喻、结尾引而不发
- **追问结构**：至少完成"现象→原因→本质追问"三级追问，但不能超过四级追问以免过于抽象

## 示例

### 示例 1

**用户输入**：
```
/哲理散文 旧手机的微信
```

**AI 处理方式**：

1. **检索参考范文**：执行 `curl "https://<your-magazine-api>.workers.dev/search?q=手机+科技+人与人的距离&top_k=3"` 和 `curl "https://<your-magazine-api>.workers.dev/search?q=对比+时代+生活&top_k=3"`。读取 ID 22027 学习"并联式片段对比"的写法，读取 ID 226 学习"重新定义常识概念"的思路。

2. **确定结构**：
   - 开头（场景式）：周末清理旧手机，打开微信，发现联系人列表里有三分之二的人——至少有两年没说过话了。通讯录越满，真正在说话的人越少。
   - 展开第一层（现象描述）：翻看聊天记录，十年前微信刚兴起那会儿，每天要和很多人说话——同事、同学、网友、同城的陌生人。现在通讯录里有800个人，但每天点开对话框的不会超过5个。
   - 展开第二层（正反对比）：表面上看，是"圈子变窄了"——但真的是这样吗？十年前那些聊得热闹的人，很多也只是"在线上热闹"。现实中见过面的没几个。技术给了我们连接的能力，但没有给我们维系连接的时间和精力。（第一层追问：为什么会这样？）
   - 展开第三层（本质追问）：真的是"越来越孤独"吗？也许正好相反——正因为知道每条消息都要花精力回复，所以才把精力留给了真正重要的人。不是通讯录变冷清了，是我们终于学会了"不回应"是一种筛选机制。十年前我们把"连接"当作目的，十年后我们才明白"不连接"也是一种选择。（第三层追问：我们会不会想反了？）
   - 比喻：旧手机像一本旧通讯录——不对，旧手机本身就是一个"社交化石"，记录着一个人社交史的全部：从渴望被所有人认识，到只想被几个人记住。
   - 结尾（意象延展式）：我没有删掉那些联系人。他们安静地躺在通讯录里，像一本旧书的目录——你不需要翻开每一页，但你知道它们曾经在那里。
   - 对比设置：十年前 vs 十年后、线上热闹 vs 线下相见、800个联系人 vs 5个对话框
   - 追问路径：现象（通讯录越满越沉默）→ 原因（时间精力有限）→ 本质追问（真的是越来越孤独吗？还是学会了筛选？）

3. **输出**：一篇 700-900 字的哲理散文，署名 `文/XXX`，从旧手机微信这个具体场景切入，完整的"现象→原因→本质追问"三级追问，一处正反对比，一个日常物象比喻（社交化石/旧书目录），结尾引而不发。

### 示例 2

**用户输入**：
```
/哲理散文 为什么我们总把最好的东西留到最后
```

**AI 处理方式**：

1. **检索参考范文**：执行 `curl "https://<your-magazine-api>.workers.dev/search?q=舍不得+使用+最好的&top_k=3"` 和 `curl "https://<your-magazine-api>.workers.dev/search?q=日常+物件+人生+道理&top_k=3"`。读取 ID 24924 学习"从一个日常动作切入，追问个没完"的写法，读取 ID 17285 学习"对比推进"的技巧。

2. **确定结构**：
   - 开头（物件式）：母亲买了一条新床单，花色很好看，她说"等客人来了再用"。那条床单在柜子里放了三年，一次客人也没来过。后来拿出来的时候，已经泛黄了。
   - 展开第一层（现象+多例并举）：家里这样的事太多了——那套好餐具一直放在橱柜最上层，那瓶好酒一直等"某个重要日子"，那件好衣服一直挂着标签在等"一个重要的场合"。但重要的场合永远在"明天"。（用多个例子并列，形成"这不是个例"的暗示）
   - 展开第二层（初步追问+对比）：我们为什么总把最好的东西留到最后？表面上是因为"珍惜"——怕用坏了、怕场合不对糟蹋了好东西。但同样的逻辑放在时间上呢——我们总说"等下次有空了再去那个地方""等忙完这阵子就好好陪陪家人"。"最后"永远不会来，因为"最后"前面那个"现在"已经被挥霍掉了。（第一层追问：珍惜还是恐惧？→ 第二层追问：时间呢？）
   - 展开第三层（本质追问）：等等——这真的是"把最好的留给最后"吗？还是说，我们其实在用"留给最后"这个说法，来逃避"配不上最好的"这种感觉？那套餐具太精美了，怕用起来不自在；那条床单太漂亮了，怕弄脏了可惜。我们不是舍不得好东西，我们是觉得自己配不上好东西。（第三层追问：真的是珍惜吗？还是在用"留给最后"来逃避"配得上"的焦虑？）
   - 比喻：我们像那只囤积松果的松鼠，把最好的果子藏到最后才吃——等冬天来了才想起来吃的时候，果子早就坏了。
   - 结尾（画面收束式）：我把那条泛黄的床单铺上了。颜色确实不如新的时候亮了，但躺上去的那一刻我还是觉得——我应该早三年铺上的。柜子最深处的那个角落里，或许还放着什么别的东西。
   - 对比设置：物品 vs 时间、珍惜 vs 恐惧、"留给最后" vs "配不上它"
   - 追问路径：现象（留好东西到最后）→ 初步追问（珍惜还是恐惧？）→ 第二层追问（时间也被这样浪费了？）→ 本质追问（其实是觉得自己配不上）

3. **输出**：一篇 750-900 字的哲理散文，署名 `文/XXX`，从一条泛黄的床单这个具体物件切入，"现象→多例并举→初步追问→深层追问→翻转追问"完整的追问链条，一个比喻（松鼠囤果），结尾回到物件但多了层意味。

写作完成后逐项自查：

- [ ] 开头是否从一个具体物件/场景/事件切入，而非抽象概念？

- [ ] 是否加了署名（`文/XXX`）？
